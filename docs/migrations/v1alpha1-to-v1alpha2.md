# Migrate SkillCard v1alpha1 to v1alpha2

SkillCard v1alpha2 makes `SKILL.md` authoritative for the Agent Skill and keeps
only distribution and catalog metadata in `skill.yaml`.

v1alpha1 cards remain readable, valid, and buildable. `skillctl` prints a
deprecation warning when it uses one; there is intentionally no migration
command.

## 1. Move Agent Skill metadata to `SKILL.md`

Keep these fields in YAML frontmatter at the start of `SKILL.md`:

```yaml
---
name: pdf-processing
description: Processes and transforms PDF documents. Use for PDF workflows.
license: Apache-2.0
compatibility: Requires poppler-utils.
metadata:
  owner: docs-team
allowed-tools: Bash Read
---
```

`name` and `description` are required. The `name` must match the skill directory
name. Agent Skills metadata values must be strings.

Move the old `spec.prompt` instructions into the Markdown body. Move any old
examples, dependencies, templates, scripts, or reference material into the
skill directory itself. Agent Skills imposes no fixed names beyond `SKILL.md`;
the conventional directories are `scripts/`, `references/`, and `assets/`.

## 2. Replace `skill.yaml`

The smallest v1alpha2 card is:

```yaml
apiVersion: skillimage.io/v1alpha2
kind: SkillCard
metadata:
  version: 1.2.0
```

The version must be a strict `MAJOR.MINOR.PATCH` base version. Prerelease stages
are generated by the lifecycle commands and must not be written here.

Optional catalog metadata is:

```yaml
metadata:
  version: 1.2.0
  title: PDF Processing
  vendor: Example Corp
  tags: [pdf, documents]
  authors:
    - name: Example Maintainer
      email: maintainer@example.com
  url: https://example.com/pdf-processing
  documentation: https://docs.example.com/pdf-processing
  support: https://example.com/support
  changelog: https://example.com/changelog
  annotations:
    com.example.security.reviewed: "true"
```

Custom annotations must use reverse-domain keys and cannot use the reserved
`org.opencontainers.*` or `io.skillimage.*` namespaces.

Remove `name`, `display-name`, `namespace`, `description`, `license`,
`compatibility`, `allowed-tools`, `provenance`, and `spec` from `skill.yaml`.
There is no namespace replacement: repository location belongs in the OCI
reference used by build/tag/push.

## 3. Validate and build

```bash
skillctl validate ./pdf-processing
skillctl build ./pdf-processing
```

The first default build creates:

```text
localhost/pdf-processing:1.2.0-alpha.1
localhost/pdf-processing:latest
```

Use an exact Podman-style build reference when you want to manage tags yourself:

```bash
skillctl build -t ghcr.io/example/skills/pdf-processing:canary ./pdf-processing
```

That command creates only the exact `canary` reference. Use `skillctl tag` for
additional aliases.

## Install provenance

v1alpha2 package content is never rewritten on install. Operational provenance
is stored at:

```text
<skills-root>/.skillimage/receipts/<skill-name>.json
```

Existing v1alpha1 installations keep their embedded provenance behavior.
